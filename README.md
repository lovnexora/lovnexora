## how i work

I like understanding systems rather than only learning their surface-level APIs.

When something breaks, I want to know:

1. what actually happened
2. why it happened
3. how to reproduce it
4. how to fix it
5. how to test the fix
6. how to keep the same bug from returning

I'm actively improving at the less glamorous parts of software engineering too:

**testing · debugging · Git workflows · code review · architecture · documentation · deployment · observability · production thinking**

Because “it works on my machine” is not, unfortunately, a deployment strategy.
